Measured 2026-09-16 while reviewing the `/compress-pdf` island (branch `compress-engine-seam`,
uncommitted). When a fifth tool page arrives, some cross-page controls pick it up and some do
not, and the difference is not obvious from the test names.

**Derived — a new page is covered automatically:**

* `src/production-build.test.ts` inline-`<style>` scan and the CSP-per-page check: walk every
  built `.html`.
* `src/built-for-origin.test.ts`: walks the built pages.
* `src/size-budget.test.ts` "states each tool page's ceilings once": globs
  `src/pages/*-pdf.astro` and compares each page's prose against `tool-host.ts`'s
  `maxInputBytes` / `maxPages`. Gated on the count.
* `tools/first-load.mjs` weighs every landing route and budgets the heaviest
  (`measured_route`), so a new page only moves the numbers if it *becomes* the heaviest.

**Hand-listed — a new page is silently omitted:**

* `src/components/error-kinds.test.ts:75` `PAGES` (and the per-page arrays in
  `FALLBACK_IS_CORRECT:61`). This is the file written *because* three hand-written kind lists
  went stale on `OutputRejected`; its own page registry is hand-written.
* ~~`e2e/origin-guard.spec.ts` route list under "every route carries the stamp"~~ — **fixed
  since**: it is derived from `dist/` (`routesInBuild()`, spec line ~157). Its count gate is a
  **floor**, `toBeGreaterThanOrEqual(7)`, and the build shipped 8 routes from 2026-09-17, so
  the floor no longer binds.
* `src/production-build.test.ts:63` `shipped` — hand-listed but gated on
  `toHaveLength(n)`, so omission fails loudly. This is the good pattern.
* Each `*-messages.test.ts` carries its own `KINDS` array (compress's is 9 entries, gated on
  length) — same stale-list shape `error-kinds.test.ts` was meant to retire.

**The island guards themselves are per-file copies with no registry at all:** the #69
capture-before-await discipline is enforced by `tool-delivery.ts`'s API shape, but whether an
island *uses* it, and whether `choose()` invalidates, is only covered by that page's own e2e
spec. `split-pdf.spec.ts:438` and `reorder-pdf.spec.ts:232/269` are the model assertions;
a new page without them has the guard untested.

**2026-09-17, the pages rework (#57 piece 3) added `/how-it-works`.** Derived and therefore
covered automatically: `public/sitemap.xml` + `robots.txt` (generated by
`tools/stage-web-engines.mjs` from a walk of `src/pages`), `tools/first-load.mjs`
`landingPages()`, `size-budget.test.ts` "weighs every route in the build, by name",
`production-build.test.ts`'s per-page CSP/inline-style scans, `built-for-origin.test.ts`,
`tools/check-live-routes.py` (and its sitemap-count cross-check at line ~469),
`e2e/origin-guard.spec.ts`. Hand-listed and NOT gated against the pages on disk:
`production-build.test.ts`'s new `folded` map (5 tool pages, `toHaveLength(5)` — a sixth tool
page would leave it green and unchecked).

The landing page's link check (`/href="\/([a-z-]+-pdf)"/`) only covers `-pdf` routes, so
`/how-it-works` is covered only by the explicit assertion added in the same change.
